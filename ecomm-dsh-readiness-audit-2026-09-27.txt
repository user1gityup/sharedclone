
=== audit:roster-capacity
Claude Opus 5.5 did a read-only audit. Nothing was edited, built or run. Only this host's code (HEAD 92cdcade3b) and its ~/.dsh/settings.yaml were read. vmixer2o2's facts come from the 2026-09-27 01:05 handoff, as relayed by its executor.

(1) The pre-written units are not honoured as a graph. The swarm and pipeline tools take no graph input. The swarm stage always asks one non-free planner seat to split the query again. The pasted LOCAL-SEAT JSON reaches that planner only as request text. provider='llama-local' then means little in any mode that writes files. Under fastest, free seats are removed, so llama-local drops out. Under economy, every eligible free seat competes on every unit, whatever the unit names. Only the 'user' profile honours the named seat, and it stages no files. The 13 pre-written units also lack files and acceptance. Economy validation rejects them for that, and a unit with no files stages nothing to commit.

(2) Limits:
- At most 32 units per run.
- Per-call caps: 600 s for llama-local, 420 s for kimi and deepseek, and a 180 s run default for any seat without its own cap.
- There is no per-unit or per-run deadline.
- Every unit in a wave runs at the same time. swarmRoster.maxConcurrent is accepted by the settings schema but silently dropped.
- Failed calls are not retried automatically. A failed unit fails everything that depends on it.
- Dead seats are probed and left out before the run. A quota or credit failure parks the pipeline, keeping finished units.
- The work goes to the repo only when every unit succeeds, so one failed unit holds back the whole commit.

(3) A llama-local code seat needs only these settings: swarmRoster enabled with wide kinds including 'any', and model Qwen3.6-35B-A3B-UD-Q4_K_M. The 600 s cap, 300 s idle limit, enable_thinking false, local, free and the :8090 address are fixed in code and cannot be set. This host's llama-local is off in both blocks, and its model is DeepSeek-Coder-V2-Lite, which has an 8192-token context.

(4) swarmRoster: kinds [] takes nothing; kinds absent takes every kind including 'any'; enabled absent follows the council seat. On this host, 8 seats accept code; fastest leaves only openai, claude-work and cheaperinference.

(5) One run cannot cover three repos. submit_to names one writer repo. File paths lose which repo they came from. Two units writing the same path abort the commit. DSH holds one pipeline at a time. So the answer is one run per repo, run one after another: users, then canna, then commerce, not canna and commerce in parallel.

Separately, the commit step refuses package.json and .env.* and aborts the whole change set when it sees one. All three repos are greenfield with no package.json.

8. The users gate needs a running service, which DSH cannot start.

Claude Opus 5.5 (read-only review; nothing was edited, built or launched). Every file is written by the DSH host process on whichever machine runs DSH. Seats only return text. The host parses the WRITE: blocks into <session workspace>\.dsh-staging\<runUUID>\<unit>\<seat>\<path>. When `submit_to` is given, it then copies the winning files into a fresh git worktree at <worktreeRoot>\<repoKey>\<runId> on branch dsh/<seat>/<runId>, and runs the setup commands, then the checks, then `git add -A` and `git commit` with hooks enabled. Last, it calls queue-build.mjs. Nothing in this path runs `git push`.

vmixer2o2's current build already contains this path. candidate-submit.ts arrived in d3f1f37e11, not in 0d49b54f8b as the brief says. d3f1f37e11 is an ancestor of f55855f248. host-commit, candidate-submit, writes, staging and swarm have a 0-line diff between f55855f248 and origin 111c359502.

Six things stop this plan from producing a working build as it stands:
1. One run can submit to only one repo. `submit_to` is a single key, and file labels lose track of which repo they came from, so users -> (canna || commerce) has to be three runs, one after another.
2. All three BUILD-BRIEFs include a `.env.example` unit. The host refuses `.env.*` paths, and one refused path cancels the commit for the whole run. The same applies to package.json, lockfiles, CI workflows and rule files.

6. The three repos must exist on vmixer2o2, and each one's origin must point somewhere permanent that has a `main` branch.
