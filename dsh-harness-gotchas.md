Traps hit while building plugins in `~\Documents\claudecode\deepseek-harness`:

- **Orphan packages break the whole build.** The root globs `packages/*/*`, so any directory without a `package.json` fails the entire tree, not just itself. Scaffold manifest-first.
- **A green build does not mean the plugin loads.** Two runtime-only failures: a client-only plugin still needs `export function apply(): void {}` in its host entry or Cordis rejects it; and `inject` must be an array (`['tools','settings']`) — there is no `{required,optional}` form, and inventing one makes the plugin wait forever on services named "required" and "optional". Always boot with `node --import tsx/esm apps/cli/src/bin.ts web` to check.
- **CSS tokens are `--dsw-alias-*`, not `--ds-color-*`.** Invented names silently fall through to hard-coded fallbacks, which is how panels ended up dark-on-light. Useful ones: `--dsw-alias-label-primary`, `--dsw-alias-label-secondary`, `--dsw-alias-interactive-bg-hover`, `--dsw-alias-bg-layer-2`, `--dsw-alias-border-l2`.
- **Type-only side-effect imports are required for Context merges**: `import type {} from '@deepseek-ai/dsh-client-locale/client'` for `ctx.locale`, `.../dsh-client-ui-settings/client` for `ctx.settingsScope`, `'@deepseek-ai/dsh-settings'` for `ctx.settings`.
- **Session logs are multi-frame zstd.** `zstdDecompressSync` decodes only the first frame; split on the magic bytes `28 B5 2F FD` and decode each.
- **KvTable writes are `put`/`delete`/`update`**, not `set`.
- Strict flags in force: `exactOptionalPropertyTypes`, `noUncheckedIndexedAccess`, `noUnusedLocals`. `readonly` on a Config interface breaks schemastery assignability.
- **Schemastery materialises defaults into nested objects, and that breaks boot.** A `z.object({ id: z.string().required() })` gets an empty `{}` default, which then fails its own required field before any code runs — the host refuses to start with a ValidationError. Use flat scalars. The same mechanism bit an `args: []` default that silently replaced a seat's real argv. Guard it with a test asserting `Config({})` resolves.
- **A settings `update` treats `undefined` as "leave unchanged", not "delete".** Clearing a field by writing `undefined` silently does nothing; write an empty sentinel (`''`, `0`) and treat that as absent on read.
- **A tool result node has no `value`/`result`/`output` field.** It carries rendered `content` blocks and a closed union of card shapes. Structured data cannot ride along — pass it as a marker inside the text and strip it in the view. Register a per-tool renderer with the keyed slot `tool.call.toolview`.
- **The budget panel keeps its own copy of the seat roster**, because client and host faces share no module. A seat added to `seats.ts` but not to `CouncilBudget.tsx` is simply invisible, with no error. `tests/roster-drift.spec.ts` is the tripwire.
- **A spawned CLI seat must be given no stdin.** Node's default `spawn` stdio is an open pipe nobody writes to and nobody closes. `codex exec` reads it, prints `Reading additional input from stdin...` and blocks forever, so the seat returns zero bytes and dies at the timeout looking merely slow — two runs burned 1210s and 588s before the model saw anything. `stdio: ['ignore','pipe','pipe']` turns that into EOF; the same call then answers in 9s. `claude -p` never waits on stdin, so only one seat shows it. Fixed 2026-09-05 in `seats.ts` `runOnce`.
- **`@openai/codex` moved its binary.** `bin/` now holds a JS wrapper; the real exe is `@openai/codex/node_modules/@openai/codex-win32-x64/vendor/x86_64-pc-windows-msvc/bin/codex.exe`. Only `codex` and `codex.cmd` reach PATH, and Node refuses to spawn a `.cmd` without a shell, so `NPM_BIN_PATHS` resolution is the only thing that makes the seat work. Never pin the absolute path in settings.yaml — it goes stale on reinstall.
- **A CLI seat inherits the host's cwd, and that feeds it the repo's CLAUDE.md.** Measured on `claude -p`: 31s median in the harness tree against 8.8s in a clean directory, and the contaminated arm answered a one-word question with 612 characters about the project's own instructions. Seats get `cwd: ~/.dsh/seat-cwd`. Safe because seats never read files themselves — the host reads and quotes them back, resolved against the configured roots.
- **`CLAUDE_CONFIG_DIR` cannot isolate the paid Claude seat.** `claude auth login` writes credentials to `~/.claude/.credentials.json` regardless of the variable, and the runtime does not fall back: a seat under an isolated config dir exits 1 with `Not logged in`. Only `claude setup-token` plus a machine-wide `CLAUDE_CODE_OAUTH_TOKEN` would work. Verified dead end on Claude Code 2.1.233 — do not retry it.
- **Verify in the compiled artifact, not the source.** A build's exit code lies when piped (`| tail` replaces the status); read the log or capture `$?` directly. And check the container, not just the content — a session file repaired correctly still broke boot because the format needs its first zstd frame to hold exactly the header line.
- **A dead seat costs a round its full retry window, not a fast failure.** `claude -p` pointed at a stopped local proxy took **180.3s** to return `Connection refused`, measured 2026-09-06. A round waits for every seat, so one dead free-claude seat set the wall time for the plan round AND the review round: 360s of a 457s council run that produced only a plan. The run looked like a hang. Fixed in `council.ts`: seats with a loopback backend are TCP-probed before round one (`probeSeat` in `seats.ts`), and any seat that fails with a connection error is skipped for the rest of the run. `fcc-control.ps1` also waits 60s, not 20s, for a cold `uv run fcc-server` — the 20s window expiring silently is what left the proxy down in the first place.
- **A killed host used to leave `settings.yaml` unwritable forever.** `withFileLock` in `packages/util/atomic-write` refused to break any lock, by design — age cannot prove an owner stopped. So when the DSH host was force-killed while holding `~/.dsh/settings.yaml.lock` (2026-09-06), every later write timed out against a dead pid, the council could not record its plan, and no Approve control could appear; the only recovery was deleting the file by hand, from outside DSH — a `workspace-write` escalation does not reach `~/.dsh` either, since the sandbox root is the workspace. The lock now records `{pid, host, boot, token}` and a contender takes it over on proof: same host, and either a pid that no longer exists (`process.kill(pid, 0)`) or a boot instant that is not this one. Another machine's lock is never broken, an unreadable lock is never broken, and a holder releases only while its own token is still in the file.
- **`tsdown --filter <pkg>` skips a UI plugin's browser bundle.** `clientBundle` names that config `<pkg>/client`, so the filter builds `lib/index.js` and leaves a stale `lib/client.js` — the host keeps serving the old panel while every test is green. Pass both `--filter <pkg> --filter <pkg>/client` with `--env.DSH_BUILD_FACE client`, and confirm the `?rev=` on `/plugins/<pkg>/client.js` changed. Rebuilding `apps/web` does not touch plugin bundles.
- **Boot-check beside a running DSH without touching it.** Set `DSH_HOME` to a temp dir holding only a junction `profiles` → `~/.dsh/profiles`, then `node --import tsx/esm apps/cli/src/bin.ts web --port 3197`. Plugins resolve through the real profile links; settings, sessions and locks stay in the temp home.
- **A hosted seat is a stream now, and a degraded run can be amended.** Two things bit on 2026-09-07. Kimi and DeepSeek sat on the run's 180s default while both CLI seats carried their own 420s caps, so a stage-2 draft cut them off mid-answer and the round lost two votes; and one non-streaming POST that runs for minutes is an idle socket, which is what `fetch failed caused by other side closed` was. `askOpenRouterSeat` now sends `stream: true` with `stream_options.include_usage`, assembles the SSE itself (keep-alive `:` comments reset an idle timer separate from the whole-call cap, and a non-event-stream content-type falls back to reading one JSON body, which is what a proxy that ignores `stream` returns), and both hosted seats carry `timeoutMs: 420_000`. Separately, a finished run is filed to `~/.dsh/council-runs/<id>.json` and `council({ resume: '<id>' | 'last' })` re-asks ONLY the seats that failed, keeps every answer already collected, re-tallies, and needs no new approval — capped at 3 amendments per run. Votes cast before a recovered answer existed are kept but reported as stale, because a vote on three answers is not a vote on five.
- **Composer Council mode ON routes every chat request to the council tool.** A DSH chat asking for any other tool (e.g. `runs list`) then "stalls" for 15+ min at "Deep diving" while the council runs; it is not a bug in that tool. Turn Council mode OFF in the composer to call ordinary tools (proven 2026-09-26 23:49: `runs list` answered in 18s). Restore it after.
- **brain-sync preset exchange used to be union-only.** `planExchange` in `.sync/brain-sync.mjs` always pulled a shared-only preset id, so a preset deleted or renamed in the UI came back next sync tick. Fixed 2026-09-26 (brain 32bbfd3): presets use tombstones (`planExchange(..., { tombstones })`, `removePresetChunks`, an empty set writes `pipelinePresets: {}`); credentials keep union behavior. Fleet round trip with vmixer2o2 proven.
