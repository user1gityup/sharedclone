> # DSH "App" Chromeless Window — Planning Round Decision
> 
> ## Selected Solution
> 
> ### 1. Window Mechanism: PWA `display: "standalone"` with `window-controls-overlay`
> 
> **Chosen mechanism.** A static web manifest served from localhost:3080 with `"display": "standalone"` and `"display_override": ["window-controls-overlay"]`, launched by opening a companion endpoint that triggers install, plus a detected-already-open shortcut path via `window.name` and `postMessage` to focus it.
> 
> **Why it wins:**
> - **Zero new dependencies.** A static `manifest.webmanifest` file and a `<link rel="manifest">` tag. No Electron, no Tauri, no native compilation, no child-process management.
> - **Windows 11 native behaviour.** Edge and Chrome both support `window-controls-overlay` on Windows 11. The OS draws its own caption buttons (snap layouts, snap groups, taskbar hover preview) inside a region the web page controls via CSS env variables `titlebar-area-x/y/width/height`. You get the exact athas.dev / gumloop.com look: DSH draws the title strip, OS draws the min/max/close dots.
> - **Same localhost app, not a fork.** The PWA loads `http://localhost:3080` — identical HTML, JS, CSS. No separate build artifact. Theme, routing, state all stay in one place.
> - **Graceful degradation.** If the browser doesn't support PWA install or WCO, "app" mode falls back to `window.open(url, '_blank', 'popup')` with the best available chrome stripping, clearly labeled as degraded, with a "best experienced in Edge/Chrome" note
