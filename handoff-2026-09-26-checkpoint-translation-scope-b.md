## How generated zh docs are maintained (the brief's research question)

Confirmed from `docs/event-producer-consumer.zh.md` / `docs/module-graph.zh.md`'s own header comment (not a script feature): the English side is machine-generated (`scripts/gen-doc-graphs.ts`, `gen-config-catalog.ts`, `gen-tool-catalog.ts` — none of these scripts have any zh/locale-aware logic at all, confirmed by grep). The `.zh.md` counterpart is a **hand-maintained reviewed translation**, kept in sync manually after each regen, then re-recorded with `--write`. The zh file's own leading HTML comment states this explicitly (translated): "The English source is generated by `<script>`; this Chinese file is the reviewed counterpart maintained through bilingual pairing. When updating: first run `pnpm run gen-*` to update English, then update this file and re-record the pair." None of these 4 catalogs use the `<!-- BEGIN/END GENERATED -->` region-marker mechanism (`partitionGeneratedRegions` finds zero regions in any of them) — the *entire* file is compared via the ordinary structural signature, so fenced code (the mermaid diagrams, the `ts config-catalog`/tool-schema declaration dumps) must stay byte-identical between languages (per the repo's normal "code blocks are verbatim" rule), while any surrounding prose is genuinely translated.
